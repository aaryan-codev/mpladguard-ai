# MPLADGuard-AI — ML Pipeline

Unsupervised anomaly detection for MPLADS project data using Isolation
Forest. This is a **decision-support tool**: it flags projects for human
review, it does **not** confirm fraud.

## Architecture

```
Raw CSV(s)
    │
    ▼
data_loader.py       load + attach dataset provenance (real/synthetic)
    │
    ▼
validation.py        clean/validate rows (dates, ranges, duplicates, negatives)
    │
    ▼
feature_engineering.py   derive 10 numeric risk features
    │
    ▼
preprocessing.py     median-impute + robust-scale (fit once, saved with model)
    │
    ▼
train.py             fit Isolation Forest per category (+ one default model)
    │
    ▼
scoring.py            normalize raw anomaly score -> 0-100 risk score
explain.py             compare features to training distribution -> risk factors
    │
    ▼
models/*.joblib + *.meta.json + registry.json
    │
    ▼
predict.py            single-project inference, used by the backend
```

## Dataset schema

See `data_loader.REQUIRED_COLUMNS` for the full list. Broadly: project
identity, financials, timeline, progress, inspections, contractor, and
procurement fields (matches the root README's dataset section).

Every row carries a `dataset_type` column: `"real"` or `"synthetic"`.
If missing, it defaults to `synthetic` (safer default). **The bundled
`ml/data/sample/sample_projects.csv` is 100% synthetic/demo data,
generated by `ml/scripts/generate_sample_data.py`, and must never be
presented as real MPLADS data.**

## Engineered features

| Feature | Formula |
|---|---|
| `cost_deviation` | `(actual_cost - estimated_cost) / estimated_cost` |
| `fund_utilization_ratio` | `utilized_amount / released_amount` |
| `financial_physical_progress_gap` | `financial_progress - physical_progress` |
| `delay_ratio` | `actual_duration / planned_duration` |
| `inspection_gap_days` | days since `last_inspection_date` |
| `contract_estimate_ratio` | `contract_value / estimated_cost` |
| `cost_per_beneficiary` | `actual_cost / estimated_beneficiaries` |
| `tender_estimate_ratio` | `winning_bid / estimated_tender_value` |
| `bid_competition_indicator` | `bid_count` (higher = more competition = lower risk) |
| `unresolved_issue_ratio` | `(issues_reported - issues_resolved) / issues_reported` |

All divisions are guarded against zero/NaN denominators (`feature_engineering._safe_divide`);
result is NaN (never inf), and NaNs are median-imputed in `preprocessing.py`.

## Category-specific models

A ₹50L bridge and a ₹50L school don't share a "normal" cost profile, so
we train **one Isolation Forest per `work_category`** that has at least
`config.MIN_CATEGORY_SAMPLES` (default **30**) rows, plus one always-on
**default/global** model trained on the full dataset.

At inference time (`predict.py`), a project's category is looked up in
`models/registry.json`; if that category doesn't have its own model
(not enough samples yet), it falls back to `default`.

Change the threshold in `ml/src/config.py`:

```python
MIN_CATEGORY_SAMPLES = 30
```

## Growing the dataset over time

Drop new verified batches of real data as additional CSVs into
`ml/data/raw/` (each with `dataset_type=real`, or pass `--dataset-type` /
rely on the default), then train on **all of them combined**:

```bash
python -m ml.src.train --use-raw
```

This concatenates every CSV in `ml/data/raw/`, deduplicates by
`project_id` (keeping the latest), and retrains from the full
accumulated dataset — never just the newest batch.

## Training

```bash
# Train on the bundled synthetic sample dataset (for testing the pipeline)
python -m ml.src.train

# Train on one specific CSV
python -m ml.src.train --data ml/data/raw/batch1.csv

# Train on everything accumulated in ml/data/raw/
python -m ml.src.train --use-raw
```

Each run:
1. Loads, validates, and cleans the data (auditable via logged issues).
2. Engineers the 10 features above.
3. Trains a default model + one model per qualifying category.
4. Saves **versioned** artifacts (timestamped filenames — never
   overwrites) to `ml/models/`: `<category>_model_<timestamp>.joblib` +
   matching `.meta.json`.
5. Updates `ml/models/registry.json` to point each category at its
   latest model.

No fabricated accuracy numbers are ever printed — this is unsupervised,
so instead you get: sample counts, % flagged anomalous, and the score
distribution actually observed.

## Risk scoring (0–100)

Isolation Forest's raw `score_samples()` is unbounded and not a
calibrated probability. We document and implement a simple, transparent
normalization in `scoring.py`:

1. At training time, record `min`/`max`/percentiles of raw scores over
   the training set → saved in the model's `.meta.json`.
2. At inference, linearly rescale a new score against that **training
   reference range**, inverted (lower raw score = more anomalous = higher
   risk), and clip to `[0, 100]`.
3. Bucket into `LOW` (0–30) / `MEDIUM` (31–60) / `HIGH` (61–100) — thresholds
   configurable in `config.py`.

## Explainability

Isolation Forest tells you a project *is* unusual, not *why*. `explain.py`
compares each engineered feature against the **training distribution**
(robust z-score vs. median/std, saved per-model in `.meta.json`) and
surfaces the most deviant features as plain-language risk factors, e.g.:

> "Gap between financial and physical progress is higher than typical
> for similar projects (value=43.0, reference median=0.9)."

This is explicitly a **statistical comparison**, not a causal claim
from the model — we never assert Isolation Forest "found" a specific
cause.

## Limitations

- Trained only on the bundled synthetic sample data until real, verified
  MPLADS data is added to `ml/data/raw/`.
- Contamination (`config.ISOLATION_FOREST_PARAMS["contamination"] = 0.08`)
  is an assumption, not derived from labeled ground truth — revisit once
  real outcomes are known.
- Category fallback to the default model means categories with <30
  samples get a less category-specific risk assessment; this is
  intentional and documented, not a bug.
- No authentication/authorization on model files; anyone with filesystem
  access can read `ml/models/`.
